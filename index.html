01

自我介绍

尽量说实话，不包装。

Background

一个放学后写代码的人

我目前在读中学，写代码的时间基本集中在放学后和周末。 这决定了我的项目有个共同特征：都是那种一两个星期能做出来的东西， 不会有宏大的架构，也不会有需要团队协作的规模。

开始做开源的原因很朴素——我自己在用某个工具时觉得别扭， 又找不到现成的解决方案，就只能自己写一个。写完发现别人可能也用得上， 就丢到 GitHub 上。巨天工作室这个名字，是在第三个项目之后才取的。

我对"优雅的架构"兴趣不大，对"能不能真的用起来"兴趣很大。 一个能跑的脚本比一份精美的设计文档有价值，这是我现在的看法， 也许过几年会变。

Taste

我喜欢什么样的软件

  • 01打开就能用，不需要先读二十页文档
  • 02报错说人话，能给出下一步该做什么
  • 03不联网也能跑核心功能
  • 04不收集数据，不弹窗求好评
  • 05卸载干净，不在系统里留下垃圾
02

现在在做什么

三条主线，外加一个正在打磨的产品。

  1. 01

    桌面工具

    把命令行里那些需要查文档才能完成的流程，包装成一个双击就能用的应用。macOS 优先，因为它就是我每天在用的系统；能跨平台的尽量跨。代表作是 WineAppRunner。

  2. 02

    网页与图形

    用 Three.js 在浏览器里做 3D 场景，以及用 Playwright 给现有编辑器注入增强。这类项目不需要用户安装任何东西，打开链接就是成品，我很喜欢这一点。代表作是 Arcadia Base 和 KittenN 主题。

  3. 03

    自动化

    把重复劳动交给脚本。桌面工具里藏着大量可以自动化的环节，装依赖、改配置、批量重命名——这些事机器做比人做可靠得多。

  4. 04

    巨天 Agent

    投入最多的一个：桌面 AI 智能体，能操作终端、管理文件、写代码、生成 PPT、语音对话。目前是预览版，还在打磨稳定性和错误提示，未开放下载。

05

一些想法

零散的、可能会变的看法。按想到先后排列。

  • NOTE 01

    工具的价值取决于最短使用路径

    一个功能再强，如果每次用都要先读文档、再改配置，它的实际使用频率会趋近于零。我把"从下载到跑起来需要几步"当成硬指标。

  • NOTE 02

    错误信息是最容易被低估的产品细节

    抛一个堆栈出去很简单，但用户看到的是"又要去搜索了"。好的错误提示应该直接给出下一步：缺什么、怎么装、命令是什么。

  • NOTE 03

    本地优先不只是情怀

    数据留在本地，意味着断网能用、意味着不用担心服务关停、也意味着不用为别人的服务器付费。对一个人维护的项目来说，这是最省事的选择。

  • NOTE 04

    不要为了显得专业而增加抽象层

    见过太多项目为了"可扩展性"提前套了三层封装，结果需求一变全得推翻。我现在的原则是：第二次用到同一段逻辑时再抽象。

  • NOTE 05

    发布半成品比不发布好

    只要核心功能跑得通、不会损坏用户数据，就值得发出去。真实用户的反馈比自己在脑子里模拟一百遍有用。

  • NOTE 06

    界面不需要漂亮，需要诚实

    状态要看得见，进度要真实，做不到的事要直说。一个会明确告诉你"这步失败了"的工具，比一个转圈圈最后假装成功的工具可靠得多。

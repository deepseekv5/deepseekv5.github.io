一些想法

零散的、可能会变的看法。按想到的先后排列。

  1. NOTE 01

    工具的价值取决于最短使用路径

    功能再强，如果每次用都要先读文档、再改配置，实际使用频率会趋近于零。

  2. NOTE 02

    错误信息是最容易被低估的产品细节

    抛一个堆栈出去很简单，但用户看到的是"又要去搜索了"。

  3. NOTE 03

    本地优先不只是情怀

    数据留在本地，意味着断网能用、不用担心服务关停、也不用为别人的服务器付费。

  4. NOTE 04

    不要为了显得专业而增加抽象层

    见过太多项目为"可扩展性"提前套三层封装，结果需求一变全得推翻。第二次用到同一段逻辑时再抽象。

  5. NOTE 05

    界面不需要漂亮，需要诚实

    状态要看得见，进度要真实，做不到的事要直说。
